# Voicemail handling

Voicemail is enabled by default in newly opened supervised-call controls. Before preparing, review/edit **Voicemail message**. Its default clearly identifies Sina's AI assistant and describes an audio test; replace it with approved campaign wording before business use. The message goes to OpenAI TTS (`gpt-4o-mini-tts`, `marin`) before dialing and is held only in browser memory. Text is limited to 1000 characters; decoded audio must be 0.5–60 seconds. Failed preparation stops setup before a phone call should start. No extension reload beyond 0.3.1 is needed for this server/page update.

After verified dialer media is ready, the application enables incoming OpenAI transcription with `gpt-4o-mini-transcribe` and server VAD, while automatic responses and outgoing audio remain disabled. It does not interpret an active phone transport as a human answer. Incoming English transcripts are checked in memory for restricted voicemail cues such as “leave a message” or “after the beep”. They are never shown or saved. Local signal processing separately detects a completed 650–1800 Hz narrow-band tone lasting 100–1500 ms. Both cues are required within bounded time windows, including up to eight seconds of ASR delay after a beep. Silence/ringing alone cannot start the message. ASR is a heuristic; uncommon greetings, other languages, atypical beeps, noise and carrier announcements can require operator review.

When both cues match, incoming OpenAI audio is muted, its automatic responses remain disabled, and the existing private bridge must acknowledge an open output gate. The pre-generated message plays into the same generated CRM microphone exactly once. After source completion plus a one-second transport drain allowance, the log records `voicemail.playback_completed`, AI resources close, and the UI says to hang up SalesGodCRM. **The phone still requires the operator to click End call.** No undocumented provider hangup endpoint or guessed selector is used. The local page cannot verify that the carrier saved the recording; `playback_completed` is not “delivered”. Never redial automatically on uncertain results.

Pause immediately stops playback and closes its output gate. Pausing or losing media during playback logs `voicemail.incomplete`; late acknowledgements do not restart it. A full-mailbox phrase produces `voicemail.unavailable`; failed ASR produces `voicemail.recognition_failed`; no greeting plus beep within 60 seconds produces `voicemail.timeout`. These states stop automatic voicemail and request review. For an actual person, the operator chooses **Customer answered — start AI**, which permanently cancels voicemail detection for that session and uses the existing conversational gates. Do not press that button just because voicemail automatically answered.
